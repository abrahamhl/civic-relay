# OEP — official project positioning
**Public name:** OEP — Offline Emergency Protocol.
**Spanish:** Protocolo de Emergencias Offline.
**Description:** Open-source research prototype for distributed emergency coordination and adaptive multi-network routing.
**Prior name:** Civic Relay / Master Emergency Routing Network. Existing GitHub repository `abrahamhl/civic-relay`, URLs, version history and legal notices retained as historical and technical identifiers. **No invented standard**: calling the project a 'protocol' does not make it an adopted IETF/ETSI/ISO emergency protocol.

## Research scope
A. Opt-in authenticated alert-zone research, with CAP format separate from issuer trust.
B. Permission-aware local device capability profiles, never silent radio toggles.
C. Explicit SAFE / SOS / other people affected / cannot determine; UNKNOWN never equals injury.
D. TTL, offline queue, dedup, simulated cross-network route selection, future real TransportAdapter.
E. Energy profiles and honest battery-vs-discovery trade-offs.

## Evidence labels
- `SIMULATED`: deterministic browser-local exercises and synthetic receipts.
- `EXPERIMENTAL_SOURCE`: unproven Android source or standalone software not yet physically measured.
- `BUILD_VERIFIED`: independently logged CI compile for exact source commit, not a hardware/field test.
- `PHYSICALLY_TESTED`: actual consented devices, timestamped logs and methodology.
- `THIRD_PARTY_VALIDATED`: external lab/assessor report for documented scope.
- `CERTIFIED`: certificate issued by appropriate body **with number, issuer, scope and validity**, if ever attained.

## Claims never permitted
No live emergency dispatch, 112 connectivity, satellite link, victim detection from silence, silent sensor activation, real measured delivery improvement, ISO/ETSI endorsement, '100% working' or '9.95/10 certified' without evidence. Keep the difference between an external safety case and a beautiful demo explicit.
